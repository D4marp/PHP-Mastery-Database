MVC Architecture

Request (HTTP GET /students) ↓ [Router] - Match URL to action ↓ [Controller] - Handle logic ↓ [Model] - Fetch data from database ↓ [View] - Render HTML response ↓ Response (HTML Page)

Separation of concerns = Easier to maintain & test

MVC separates our application into three parts. Model handles data, View handles presentation, and Controller handles the logic connecting them. This makes code cleaner and easier to maintain.

All operations follow a similar pattern: accept input, validate it, modify database, return response. This consistency makes the application predictable and maintainable.

The Model - Student.php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Student extends Model
{
    protected $fillable = [
        'nim',
        'name',
        'email',
        'phone',
        'address',
        'major'
    ];
}

Key Points: • Represents students table • $fillable = Mass assignment protection • Automatic timestamps (created_at, updated_at)

The Model is our bridge to the database. By defining $fillable, we ensure only specific fields can be mass-assigned, preventing security vulnerabilities. Eloquent handles all database operations automatically.

The Controller - StudentController.php (1/2)

public function index()
{
    $students = Student::all();
    return view('students.index', compact('students'));
}

public function create()
{
    return view('students.create');
}

public function store(Request $request)
{
    $validated = $request->validate([
        'nim' => 'required|unique:students',
        'name' => 'required',
        'email' => 'required|email|unique:students',
        'phone' => 'required',
        'address' => 'required',
        'major' => 'required'
    ]);

    Student::create($validated);
    return redirect('/students')
        ->with('success', 'Student added successfully');
}
These are the CREATE and READ operations. Store method validates input before saving, ensuring data integrity. The validate method throws exception if validation fails, which we handle in the view with error messages.

The Controller - StudentController.php (2/2)

public function edit(Student $student)
{
    return view('students.edit', compact('student'));
}

public function update(Request $request, Student $student)
{
    $validated = $request->validate([
        'nim' => 'required|unique:students,nim,'.$student->id,
        'email' => 'required|email|unique:students,email,'.$student->id,
        'name' => 'required',
        'phone' => 'required',
        'address' => 'required',
        'major' => 'required'
    ]);

    $student->update($validated);
    return redirect("/students/{$student->id}")
        ->with('success', 'Student updated');
}

public function destroy(Student $student)
{
    $student->delete();
    return redirect('/students')
        ->with('success', 'Student deleted');
}
These are UPDATE and DELETE operations. Notice in update() we exclude the current record from uniqueness check. This prevents "your own email is already taken" errors.

Routing & REST Endpoints

// routes/web.php

This single line generates 7 routes:

POST/studentsstore()Save new
GET/students/{id}show()View detail
GET/students/{id}/editedit()Edit form
PUT/students/{id}update()Save changes

REST means Representational State Transfer. Our routes follow REST conventions: GET for reading, POST for creating, PUT for updating, DELETE for removing. This makes our API predictable and follows web standards.

Form Validation & Error Handling


<form action="/students" method="POST">
    @csrf
    
    <div>
        <label>NIM</label>
        <input type="text" name="nim" 
               value="{{ old('nim') }}">
        @error('nim')
            <span style="color: red;">{{ $message }}</span>
        @enderror
    </div>

    <div>
        <label>Email</label>
        <input type="email" name="email">
        @error('email')
            <span style="color: red;">{{ $message }}</span>
        @enderror
    </div>

    <button type="submit">Save Student</button>
</form>
The @csrf directive adds CSRF token protection. The @error directive displays validation errors. The old() function repopulates form fields after validation failure, improving user experience.

Security Features Built-In

🔐 CSRF Protection (Cross-Site Request Forgery)

✓ @csrf token in every form prevents unauthorized requests

🔐 Mass Assignment Protection

✓ $fillable whitelist prevents attackers from modifying other fields

🔐 SQL Injection Prevention

✓ Eloquent ORM uses parameterized queries automatically

🔐 Input Validation

✓ Server-side validation ensures data integrity

🔐 Password Hashing (Built-in)

✓ Laravel provides bcrypt hashing for authentication

These security features come built-in with Laravel. You don't have to implement them from scratch. This is one of the biggest advantages of using a mature framework - security best practices are baked in.

Setup & Running the Application

# 1. Clone or extract project

# 2. Install dependencies
composer install

# 3. Create environment file

php artisan key:generate

# 5. Create database
